# 皮肤科专题订单页设计规格

日期：2026-07-24  
状态：已确认，待实施计划

## 1. 页面目标与范围

订单页仅展示皮肤科专题产生的服务订单，不包含挂号、处方、住院、全院自助开单或其他科室订单。

页面帮助用户完成三件事：

1. 找到本人及关联就诊人在皮肤科专题开立的订单。
2. 识别订单状态、金额、院区和下一步动作。
3. 进入订单详情，或继续处理待结算订单。

姓名与卡号必须遵守 `DESIGN.md` 的脱敏规则。首版使用皮肤科专题现有数据方式完成页面流程，真实接口接入不改变组件边界和页面结构。

## 2. 方案与路由架构

采用独立订单列表页与独立订单详情页：

- 订单列表：`/pages/dermatology/orders/index`
- 订单详情：`/pages/dermatology/order-detail/index?orderId=<订单编号>`
- 皮肤科首页：`/pages/dermatology/index`

独立路由用于保证刷新、分享、返回、滚动恢复和订单深链定位稳定。现有皮肤科首页内部的临时订单状态不作为长期订单页架构。

入口：

- 皮肤科首页右下角“订单”。
- 开单成功页“查看订单”。
- 订单详情页返回订单列表。
- 空状态“去选择服务”返回皮肤科首页。

成功页跳转订单列表时携带新订单编号；列表首次展示时仅高亮对应订单一次，不循环播放。

## 3. 信息层级与字段

信息优先级：服务名称与订单状态；院区、金额与下单时间；脱敏就诊人及卡号；查看详情或去结算。

状态集合：全部、待结算、已结算、已取消。不使用“处理中”等无法明确指导下一步的状态。

```ts
type DermatologyOrderStatus = 'pending' | 'settled' | 'cancelled'

interface DermatologyOrder {
  orderId: string
  serviceName: string
  status: DermatologyOrderStatus
  area: '鼓楼' | '五四北'
  orderTime: string
  amount: number
  patientNameMasked: string
  patientCardMasked: string
  patientRelation?: string
  canSettle: boolean
}
```

金额显示为人民币格式；时间统一为 `YYYY-MM-DD HH:mm`；列表按下单时间倒序排列。

## 4. 页面结构

```text
PortalNavBar
  └─ 院区筛选
      └─ 说明提示卡
          └─ 订单内容区
              ├─ 左侧状态分类
              └─ 右侧订单卡片列表
```

### 4.1 顶部导航

- 标题：订单。
- 使用 `PortalNavBar secondary`。
- 接入 `usePageScroll`，初始透明，滚动后使用公共毛玻璃遮罩。
- 不在页面内重写导航渐变高度。

### 4.2 院区筛选与说明

- 鼓楼院区、五四北院区。
- 延续皮肤科专题现有院区 Tab 与橙色弧线动效。
- 使用公共吸顶结构，不自行实现 sticky 定位。
- 说明文案：查看您的皮肤科服务订单记录。
- 说明卡不承担筛选或跳转功能，使用项目图标，不使用 emoji。

### 4.3 状态分类与列表

- 左侧分类：全部、待结算、已结算、已取消。
- 右侧为订单卡片列表。
- 状态分类延续皮肤科首页侧栏语言，点击热区不小于 `88rpx`。
- 多卡列表使用 `.yh-secondary-list-stack`。

### 4.4 订单卡

每张卡片包含服务名称、状态、院区、下单时间、金额、脱敏就诊人、脱敏卡号和 `PortalRowArrow`。

- 待结算显示“去结算”。
- 已结算显示“查看详情”。
- 已取消不显示主操作。
- 整张卡片可进入详情。
- “去结算”使用独立事件并阻止卡片点击冒泡。

## 5. 视觉方向与 Token

页面延续皮肤科专题视觉，不使用全院蓝色作为主色。用户最新专题色要求优先于 `DESIGN.list.md` 默认蓝色视觉，但页面骨架、尺寸、卡片和交互规则仍遵守公共规范。

专题 Token 应集中定义，不在页面选择器中散落硬编码：

- 主色：`#18A65E`
- 深色正文绿：沿用专题现有高对比度绿色
- 页面底：沿用皮肤科浅绿灰底
- 卡片底：白色
- 待结算：暖橙
- 已结算：专题主绿
- 已取消：中性灰
- 金额：沿用当前订单金额红色

白色圆角卡片使用轻描边和低对比度阴影。卡片只保留三级信息层级，不叠加无业务含义装饰。字号遵守项目 `750px @2x` 规则。自定义按钮必须洗白微信默认样式，图标保持原比例并优先复用项目 SVG。

## 6. 组件拆分

### 6.1 页面组件

`DermatologyOrdersPage`

- 管理加载、错误、院区、订单状态、列表缓存与滚动位置。
- 负责路由参数和刷新。

`DermatologyOrderDetailPage`

- 根据 `orderId` 获取订单详情。
- 展示订单状态、服务信息、就诊人和下一步操作。

### 6.2 业务组件

- `DermatologyAreaTabs`：院区选择、弧线位置和切换事件。
- `DermatologyOrderStatusRail`：状态选中态、按压态和可选数量徽标。
- `DermatologyOrderCard`：呈现单个订单并抛出 `open-detail`、`settle` 事件，不直接请求接口或改变路由。
- `DermatologyOrderSkeleton`：结构与正式卡片一致，避免首屏布局跳动。

### 6.3 公共组件

- `PortalNavBar`
- `PortalRowArrow`
- `PortalEmptyState`
- `.yh-secondary-page`
- `.yh-secondary-content`
- `.yh-secondary-list-stack`
- `.yh-secondary-card`

订单列表不使用 `FixedBottom`，因为不存在固定全局主操作。订单卡不使用完整 `PortalUserCard`，避免列表信息过重。业务组件先保留在皮肤科域内，不提前提升为全院公共组件。

## 7. 页面状态

### 7.1 正常状态

- 默认院区为进入页面前在皮肤科首页选择的院区；无上下文时默认鼓楼。
- 默认状态为全部。
- 数据按时间倒序。
- 返回列表时恢复院区、状态和滚动位置。

### 7.2 加载状态

- 首次进入显示三张订单骨架卡。
- 院区与状态筛选保持可见。
- 防止重复请求。
- 筛选切换只更新列表区域。
- 已缓存组合先展示缓存，再后台刷新。

### 7.3 空状态

统一使用 `.yh-secondary-card.yh-empty-state-screen` 包裹 `PortalEmptyState`。

- 全部为空：暂无皮肤科服务订单。
- 待结算为空：暂无待结算订单。
- 已结算为空：暂无已结算订单。
- 已取消为空：暂无已取消订单。

操作：全部为空时显示“去选择服务”；当前院区为空但另一院区有数据时显示“查看另一院区”。

### 7.4 错误状态

- 文案：订单加载失败，请检查网络后重试。
- 操作：重新加载。
- 不显示技术错误码。
- 有缓存时保留缓存并显示非阻断提示。

### 7.5 分页状态

首版数据量较小时不做无限滚动。接口存在分页时，在列表底部显示局部加载和“没有更多了”，不使用整页 Loading。

## 8. 主要交互与动效

### 8.1 院区切换

- 橙色弧线横向移动约 `200ms`。
- 文字颜色同步变化。
- 列表淡入上移约 `200ms`。
- 不显示 Toast。

### 8.2 状态切换

- 点击热区至少 `88rpx`。
- 更新选中态并将列表滚动到顶部。
- 已缓存的数据不重复阻塞加载。

### 8.3 订单卡

- 按压缩放约 `0.98`，时长 `100–120ms`。
- 页面前进使用 `200–240ms` 轻微横向淡入。
- 返回后恢复原列表位置。
- 尊重减少动态效果设置。

### 8.4 去结算

- 按钮进入 Loading 并禁用重复点击。
- 成功进入结算流程。
- 失败显示明确业务原因和重试操作。

### 8.5 下拉刷新

- 刷新当前院区和状态组合。
- 刷新成功使用轻提示，不打断浏览。

## 9. 数据流与缓存

1. 页面读取路由参数、皮肤科首页院区上下文和筛选缓存。
2. 以 `area + status` 作为请求与缓存键。
3. 无缓存时显示骨架；有缓存时先显示缓存再刷新。
4. 卡片点击仅传递 `orderId` 到详情页。
5. 详情返回时恢复筛选条件和滚动位置。
6. 开单成功返回列表时刷新当前组合，并定位新订单。

筛选缓存只服务当前登录会话；切换账号或退出登录必须清空。

## 10. 可访问性与触控

- 所有按钮、Tab、状态分类的实际触控区域至少 `88rpx × 88rpx`。
- 卡片整张可点击，同时保留明确按压态。
- 状态不只依赖颜色，必须显示文本。
- 小字号绿色文字使用深色版本保证白底对比度。
- 长服务名最多两行，超出省略。
- 时间、金额和卡号禁止异常换行。

## 11. 验收标准

- 入口仅展示皮肤科专题订单。
- 四种筛选状态均能正确切换并显示对应列表或空状态。
- 院区切换不显示多余 Toast。
- 订单卡字段完整，姓名与卡号均脱敏。
- 待结算操作具备 Loading、防重复点击、成功与失败反馈。
- 点击卡片进入正确订单详情。
- 返回后恢复院区、状态和滚动位置。
- 首次加载、筛选加载、空状态、错误状态均有完整反馈。
- 触控区域不小于 `88rpx`。
- 页面遵守安全区、导航毛玻璃、卡片与动效规范。
- 微信小程序生产构建通过。

## 12. 非目标

首版不包含全院多科室订单、退款、发票、评价、物流、售后、复杂搜索、日期筛选、多选、批量结算或全院通用订单中心。
